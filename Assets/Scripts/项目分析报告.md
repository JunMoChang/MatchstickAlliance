## 二、严重 Bug（✅ 已全部修复 2026-04-29）

### 2.1 ✅ EndedGame.GetNextLevel() 数组越界

**文件：** `Assets/Scripts/GamePlay/UI/EndedGame.cs:60`

```csharp
// 当前代码（错误）：
return currentIndex <= currentChapter.levelData.Length
    ? currentChapter.levelData[currentIndex] : null;

// 应为：
return currentIndex < currentChapter.levelData.Length
    ? currentChapter.levelData[currentIndex] : null;
```

当通关章节最后一关时，`currentIndex` 等于 `Length`，条件 `<=` 为 true，会越界访问 `levelData[length]` 导致 `IndexOutOfRangeException`。

### 2.2 ✅ BoxColliderManager 编译错误

**文件：** `Assets/Scripts/GamePlay/Role/RoleBoxCollider/BoxColliderManager.cs:4`

```csharp
using UnityEditor;  // ← 这行会导致构建失败！
```

`UnityEditor` 命名空间在运行时构建中不可用，必须用 `#if UNITY_EDITOR` 包裹。同时 `OnDrawGizmos` 中使用了 `Handles` 类，也需要条件编译保护。

### 2.3 ✅ SceneLoader.TriggerPrepare 异常导致加载卡死

**文件：** `Assets/Scripts/GamePlay/Scene/SceneLoader.cs`

```csharp
private void TriggerPrepare(Action handler)
{
    var delegates = handler.GetInvocationList();
    foreach (var d in delegates)
    {
        d.DynamicInvoke();          // 如果这里抛异常
        pendingReadyCount--;        // 这行永远不会执行
    }
}
```

任何订阅者的准备委托抛出异常，`pendingReadyCount` 永远不会到 0，加载流程永久卡死。需要 try-catch。

### 2.4 ✅ MainMenuController 关卡按钮始终绑定第一章

**文件：** `Assets/Scripts/GamePlay/UI/MainMenuController.cs:120`

`BuildLevel()` 中始终用 `levelChapters[0]` 遍历关卡数量，`SwitchChapter()` 切换了章节标题但没有重建关卡按钮。切换章节后显示的关卡按钮仍然是第一章的。

## 三、中等 Bug

### 3.1 ✅ 暂停菜单未暂停游戏

**文件：** `Assets/Scripts/GamePlay/UI/PauseGame.cs`

```csharp
public void PauseButtonOnClick()
{
    pauseGo.SetActive(!pauseGo.activeInHierarchy);
    // 缺少: Time.timeScale = pauseGo.activeInHierarchy ? 0f : 1f;
}
```

暂停面板显示时游戏逻辑继续运行，敌人移动、计时器等都未冻结。

### 3.2 ✅ LevelManager.OnLevelEnded 多订阅者保护

**文件：** `Assets/Scripts/GamePlay/GameModel/Level/LevelManager.cs`

事件签名是 `Action<Action>`（有序回调链，故意设计：先掉落奖励，回调再弹窗）。当前只有一个订阅者，工作正常。为防未来多加订阅者导致回调被重复触发，添加了 `levelEndInProgress` 幂等守卫。

### 3.3 ✅ PlayerController 未检查 Nullable 返回值

**文件：** `Assets/Scripts/GamePlay/Role/PlayerController.cs:55-59`

```csharp
RoleRegistry.RoleEntry? entry = roleRegistry.GetEntry(selectedRole[i].roleName);
GameObject instance = Instantiate(entry.Value.prefab, transform);
// entry 可能为 null，直接 .Value 会抛 InvalidOperationException
```

### 3.4 ✅ LevelContext ScriptableObject 持久化脏数据

**文件：** `Assets/Scripts/GamePlay/GameModel/Level/LevelContext.cs`

`ScriptableObject` 作为跨场景运行时状态传递。在 Editor 中停止运行后，`selectedHeroes`、`currentLevel` 等数据会残留在 SO 资产文件中。应在运行时使用 `ScriptableObject.CreateInstance<LevelContext>()` 而非直接引用资产。

### 3.5 PlayerInputHandler.SwitchStrategy() 从未被调用

**文件：** `Assets/Scripts/GamePlay/Role/PlayerInputHandler.cs`

存在切换角色的方法和切换按钮绑定逻辑，但没有任何地方调用它。玩家无法在战斗中切换控制的角色。

### 3.6 BoxColliderManager 持续碰撞体不造成伤害

**文件：** `Assets/Scripts/GamePlay/Role/RoleBoxCollider/BoxColliderManager.cs`

`EnableBox`/`DisableBox` 管理持续碰撞盒，但触发回调 `TriggerEnter2D`/`TriggerStay2D` 中只有 `Debug.Log("敌人受到攻击")`，没有实际伤害计算。目前只有 `InstantHit` 方法能造成伤害，且伤害值硬编码为 10000。

### 3.7 ✅ BattleBackgroundParallax 云层循环逻辑缺陷

**文件：** `Assets/Scripts/GamePlay/UI/BackgroundParallax/BattleBackgroundParallax.cs:51`

```csharp
if (cloudX[i] + cloudWidth * 0.5f < -halfCanvas)
    cloudX[i] = cloudWidth + halfCanvas;
```

云层离开左边界后被重置到右边界外（`cloudWidth + halfCanvas`），导致出现可见空白间隙。且 `cloudSpeeds` 硬编码 4 个值但 `clouds` 数组长度可变，数量不匹配时会越界。

## 四、设计问题

### 4.1 单例过度使用

以下类均为 MonoBehaviour 单例模式（`static Instance` + `DontDestroyOnLoad`）：

- `LevelManager`
- `RewardSystem`
- `SceneLoader`
- `UIManager`
- `PlayerController`
- `SpawnPoint`

这导致：
- 隐式耦合，所有系统可直接访问任意单例
- 初始化顺序依赖脆弱
- 难以进行单元测试
- `SpawnPoint` 未使用 DontDestroyOnLoad 且无重复检查

### 4.2 硬编码常量散布各处

| 硬编码值 | 位置 | 影响 |
|----------|------|------|
| `strategies[2]` | PlayerInputHandler | 队伍只能 2 人 |
| `skillTimers[4]` | SunWuKongStrategy | 技能固定 4 个 |
| `maxCombos = 5` | SunWuKongData | 连击数不可变 |
| `damage = 10000` | BoxColliderManager | 伤害无意义 |
| `WaitForSeconds(1f)` | RewardSystem | 等待时间不可配 |
| `cloudSpeeds[4]` | BattleBackgroundParallax | 云数量固定 |

### 4.3 RoleRuntimeData 死代码

**文件：** `Assets/Scripts/GamePlay/Role/RoleData/RoleRuntimeData.cs`

定义了 `RoleStatRuntime` 和 `RuntimeSkillData`（含冷却管理逻辑），但：
- `RoleRuntimeData` 中没有对应字段实例化它们
- `SunWuKongStrategy` 自行维护 `skillTimers[]` 数组做冷却管理
- 整个类文件中无任何代码被引用

### 4.4 Strategy 模式缺乏抽象基类

`IRoleStrategy` 接口要求每个实现自己管理：
- `RoleContext`、`Animator`、`Rigidbody2D`、`BoxColliderManager` 缓存
- 冷却系统
- 运动数据字典

这些共性代码会在每个策略实现中重复。应有 `abstract class RoleStrategyBase`。`YasuoStrategy` 中出现的 `Destroy()` 方法未被加入接口，说明作者意识到需要生命周期管理但未完善。

### 4.5 数据分散

一个敌人的完整配置被拆分到：
- `EnemyData`（血量、伤害、成长率）
- Prefab 上的 Animator/组件（行为参数）
- 脚本中硬编码（如果攻击逻辑写在 MonoBehavour 上）

角色的技能数据分散在：
- `RoleBaseData.skills`（图标、基础伤害/冷却）
- `SunWuKongData.skillCooldowns`（实际冷却时间，与父类重复）
- `RoleRuntimeData.RuntimeSkillData`（运行时冷却状态，未使用）
- `SunWuKongStrategy` 内部 `skillTimers[]`（实际使用的冷却计时）

### 4.6 两套 UI 系统混用

| 系统 | 使用场景 |
|------|----------|
| UI Toolkit (UI Document) | 主菜单 |
| 传统 uGUI | 战斗内暂停、结束面板、加载进度条 |

这增加了维护复杂度和渲染开销。

### 4.7 Newtonsoft.Json 依赖与安全隐患

- 增加了约 500KB 的包体积
- `TypeNameHandling.Auto` 允许通过 JSON 注入实例化任意类型（在单机游戏中风险较低但应予注意）
- 没有存档版本号字段，版本更新时旧存档可能崩溃

## 六、性能与健壮性问题

### 6.1 EnemyManager 轮询等待

`WaitForWaveClear()` 每帧遍历 `activeEnemies` 列表检查 null 引用。对于大关卡或长波次，应使用事件驱动（每个敌人死亡时通知管理器）。

### 6.2 SceneLoader 0.5 秒轮询

加载协程中 `WaitForSeconds(0.5f)` 造成：
- 进度条更新粗糙（每 0.5 秒跳一次）
- 最小加载时间至少 0.5 秒

### 6.3 SaveManager 无异常处理

`Save()` 和 `LoadData()` 直接进行文件 I/O，无 try-catch。磁盘满或权限错误会导致游戏崩溃。移动端无 `OnApplicationPause` 存档，强制杀进程会丢失进度。

### 6.4 字符串查找脆弱

- `GameObject.FindGameObjectWithTag("Player")` — EnemyManager
- `Q<ProgressBar>("progress-bar")` — LoadingSceneController
- `if (label == "装备")` — MainMenuController.OnNavClick

### 6.5 BoxColliderManager 碰撞结果上限

```csharp
Collider2D[] enemies = new Collider2D[5]; // 固定 5 个上限
```

超过 5 个敌人同时处于判定范围时会被静默忽略。
